# NeuralFusion Case Study

NeuralFusion is the substantial real-project acceptance case for vLadder's C++, lifetime, GPU, and
application-promotion boundaries. The studies used production translation units and a pinned local
RTX 5080 system. They are evidence of one application and hardware target, not general speedup
claims.

## What Changed

The accepted remote-only presentation realization removed a GPU intermediate with no independent
observer under the declared contract. The modeled 1080p path eliminated 49,766,400 bytes per frame.
Boundary helpers received 7/7 expected Z3 outcomes and 5/5 Alive2 refinement results. Application
oracles compared output hashes and GPU pixels.

## Physical Result

Fresh installed-skill measurements reported 53.99% to 79.13% GPU-region latency reduction across
720p to 1440p full/sparse cases. The live UDP-to-software-visible boundary improved 69.87%.
The paced 60 Hz end-to-end boundary improved only 0.52%, with a 95% bootstrap interval of 0.49% to
0.54%. A small client-work submetric regressed 10.89% with an interval reaching zero and was not
reported as a win.

The difference is the central result: a large load-bearing regional reduction can produce a small
end-to-end effect when frame pacing and other stages dominate the observable boundary.

## C++ Coverage Evolution

The 46-region audit initially accepted no direct arbitrary-C++ rewrites. Later bounded frontends
captured aggregate results, byte spans, helpers, multi-exit CFGs, local state projections, and
extractable nested regions. The v4 acceptance run materialized twelve local proof units and source
candidates across eight regions while retaining allocator, destructor, exception, callback,
external API, and concurrent publication boundaries.

This is a success in semantic coverage and proof scoping, not a claim that all 46 owning functions
were automatically optimized. See the detailed reports in `docs/neuralfusion-*.md`.

## Reproduction Boundary

The public repository contains the vLadder manifests, methodology, and summarized evidence, but not
the NeuralFusion source tree or private runtime traces. Reproduction requires the separately pinned
NeuralFusion revision, its dependencies, the declared hardware, and the production workloads.
