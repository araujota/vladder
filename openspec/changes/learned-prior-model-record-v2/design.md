## Context And Research

- ProGraML represents programs as directed attributed multigraphs with data, control, and call
  relations: <https://arxiv.org/abs/2003.10536>.
- Learned accelerator cost models pair graphs and candidate configurations with physical outcomes:
  <https://research.google/pubs/a-learned-performance-model-for-the-tensor-processing-unit/>.
- NIST SP 800-188 requires an explicit data-sharing model, measurable disclosure-risk controls,
  and warns that masking or repeatable hashes alone do not establish anonymity:
  <https://doi.org/10.6028/NIST.SP.800-188>.
- The NIST Privacy Framework treats privacy controls as lifecycle and governance decisions rather
  than one serialization filter: <https://www.nist.gov/privacy-framework>.

## Record Boundary

One model-ready bundle contains three normalized entity classes:

1. A semantic root with bounded attributed graph topology and contract features.
2. One or more candidate actions referencing that root and carrying hardware/workload context.
3. Append-only observations referencing candidates.

Candidates sharing `(root, hardware, workload)` form one ranking group. The model learns relative
search value within a group. Source language is diagnostic metadata only and is excluded from the
primary feature path.

## Privacy Profile

The profile is `enterprise-graph-deidentification-v1`.

- Never transmit source, paths, symbols, user-defined type names, raw literals, IR, assembly,
  prompts, proofs, traces, patches, or compilation databases.
- Replace source node IDs with bundle-local contiguous integers.
- Preserve only public vLadder node, relation, contract, action, hardware, and workload vocabulary.
  Unknown text becomes `other`; it is not sent as a deterministic raw hash.
- Bucket source-derived sizes and cardinalities. Preserve exact values only for public grammar
  parameters generated by vLadder, such as unroll or tile choices.
- Derive root, candidate, observation, and project identities with HMAC-SHA256 under an
  installation-local random consent-epoch key. The key never leaves the host.
- Label the record `pseudonymized_structural_data`, because topology can still fingerprint a
  proprietary algorithm. Do not call it anonymous in contracts or user-facing notices.
- Bound each graph and payload. Oversized roots remain local and produce an explicit export gap.

## Consent Migration

Training consent receives a scope-specific policy version. A decision made under the previous
feature/hash notice is stale for v2 graph topology and is reported as `unknown`. The agent must show
the new notice and record a new opt-in or opt-out. Review consent is migrated independently because
its disclosure class is unchanged.

## Storage

Convex stores immutable v2 bundles, records their root IDs, and indexes bundle identity, consent
epoch, and moderation state.
Contributor capabilities remain append-only `training:write`; there is no public v2 read query.
Moderation applies to the bundle. Offline maintainers may export approved rows with deployment
authority and ingest them into a root-grouped prior store.

## Model Use

The initial pooled prior may consume v2 records immediately. A graph backend consumes node and edge
arrays without changing the storage contract. Search remains:

`legal enumeration -> prior ranking -> baseline + exploitation + exploration -> proof -> compile -> benchmark`.

The model cannot establish legality or equivalence, suppress the baseline, or authorize promotion.

## Compatibility

V1 records remain accepted at `/api/training` as telemetry. V2 records use `/api/training/v2`.
Historical v1 hashes cannot reconstruct topology and are never represented as graph roots.
